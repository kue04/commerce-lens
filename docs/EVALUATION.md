# 离线评测与真实模型验收边界

本轮全部使用本地 PostgreSQL 和确定性解析，外部模型调用次数为 0。Pi Core 的工具选择、一次修订与 429 重试由明确的 faux provider 在集成测试中验证；它不代表 DeepSeek 的回答质量或账号可用性。

## 案例与独立预期

evals/cases/offline-v1.json 包含 120 个案例：80 可回答、20 澄清/缺核心数据、20 权限/注入攻击。dev/frozen-test 各 60，按照 family 分开；同一模板的五个问法留在同一个 split。覆盖 S01—S12 场景，业务表中仅有观测明细，不插入场景标签或答案。

expectedIntent 为人工指定的指标、窗口和维度，expectedValues 从 evals/oracles/window.sql 的独立标量子查询获得并冻结。运行时只把 question/body 发给 API，expectedIntent/Values 不进入请求或模型。冻结文件具有 manifest hash；改动需要创建新版本，保留旧结果。

`npm run eval:offline`：dev 一次，冻结集三次，共 240 次执行；硬条件为意图、数值、贡献守恒、合法终态、有效证据引用、无禁止断言和模式标识正确。攻击样本要么契约层拒绝，要么在字典/权限门禁终止；前后对照业务订单数与金额，检查未发生写入。

输出 offline-*.json 保留逐例结果、caseHash、环境和失败信息，不覆盖旧结果。audit-*.json 包含 20 份用于人工抽样复核的完整报告；当前标记 automated-evidence-audit 与 humanReviewCompleted=false，不能据此声称两名人员已审核。

## 基线与不能推导的结论

- A 固定规则解析+SQL：本次实际测量的确定性系统，不具备开放式语言泛化能力。
- B 单次模型工具选择：NOT_RUN，按用户要求不调用外部模型。
- C Pi 完整真实模型多轮：NOT_RUN，按用户要求不调用外部模型。

不能以 A 的通过率代替 B/C，不能用 faux provider 的预设工具调用证明模型会正确选择工具。没有虚构 85% 模型完成率、真实供应商成本或人工效率提升。

`npm run benchmark:local` 使用 90 天 100000 订单/200000 行、单用户、真实 loopback HTTP，预热 20 次再测量 100 次到报告读取完成的耗时。模型调用为零，结果只表示本地确定性管线；bench 的创建任务速率上限显式提高到 1000/min，普通 API 仍为 60/min。

## 失败与修复记录

首次大规模完整报告性能测试失败：Top-N 的“其他”行字段构造顺序与常规贡献行不同，旧 JSON hash 依赖属性顺序，报告验证拒绝。没有把失败删除为成功；新增实际残差行→证据→落库报告的回归测试，新证据标记 sha256-canonical-json-v1，按规范 JSON 排序计算 hash，并兼容读取旧算法证据。修复后重新运行性能测试。原始失败事实与修复依据保留在本记录，不将其隐藏为网络波动。

后续用户允许真实供应商调用时，先用 dev 案例验证连通性和 10 个支付案例，再运行 B/C 的冻结集三次。调优只读 dev，最终冻结结果保留，不在看到冻结失败后改标签或删案例。
